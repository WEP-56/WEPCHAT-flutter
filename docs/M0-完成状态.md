### 3. `lib/storage/` 层（实施 TODO §9）

**架构**（存储设计 §1–§10）：
- **DB isolate**：长驻，持唯一写连接，请求经 `SendPort` 串行
- **表结构**：`sessions` / `entries` / `blobs` / `blob_refs` / `runs`
- **迁移框架**：`Migration` 列表 + `applied_migrations` 表，支持拒绝降级
- **payload 三态**：json / gzip / external（4KB / 256KB 阈值）
- **三条核心查询**：
  1. 组装上下文：`seq >= base_seq` 顺序全取
  2. 界面分页：尾部 N 条，翻页支持
  3. 会话列表：只读元信息，不碰 payload

**文件清单**（18 个文件，97KB）：

```
lib/storage/
├── storage.dart              barrel export，唯一公开接口
├── wep_storage.dart          公开 API（createSession / appendEntry / ...）
├── storage_isolate.dart      isolate 宿主：spawn / send / close
├── isolate_protocol.dart     请求/响应类型（25 种）
├── db_worker.dart            isolate 内执行者：分派请求 + 事务包装
├── migration.dart            迁移框架 + 5 张表的建表语句
├── models.dart               枚举：EntryType / EntryRole / StopReason / ...
├── session_record.dart       SessionRecord / SessionSummary
├── entry_record.dart         EntryRecord / NewEntry
├── session_dao.dart          sessions 表读写
├── entry_dao.dart            entries 表读写（append + 三条读法）
├── run_dao.dart              runs 表：start / finish / reconcile
├── blob_store.dart           内容寻址存储 + GC（两级目录 + 引用计数）
└── payload_codec.dart        三态编码（json / gzip / external）
```

**关键设计**：
- **取号原子化**：`UPDATE sessions SET head_seq = head_seq + 1 WHERE id = ? RETURNING head_seq` 防并发撞号
- **派生状态**：`provider_id` / `model_id` / `thinking` 是缓存列，权威值靠 `*_change` 条目回放
- **汇总增量更新**：`cost_total = cost_total + ?` 而非全扫，避免 O(n²)
- **blob 先写再 rename**：原子化文件落盘，防断电留下半成品
- **GC 先删行再删文件**：防悬挂引用，孤儿文件可下次扫掉
