# 记忆功能优化总结

## 问题修复

### 1. ✅ UI 初始化错误
**问题**：`dependOnInheritedWidgetOfExactType` 在 `initState` 中被调用
**原因**：在 widget 树未完全构建时访问 `InheritedWidget`
**解决**：使用 `WidgetsBinding.instance.addPostFrameCallback()` 延迟加载

### 2. ✅ 噪音日志过滤
**问题**：`[ERROR:flutter/shell/platform/common/accessibility_bridge.cc(114)]` 频繁输出
**原因**：Flutter 引擎已知问题，不影响功能
**解决**：在 `windows/runner/main.cpp` 中设置环境变量过滤日志

```cpp
SetEnvironmentVariableA("FLUTTER_ENGINE_LOG_LEVEL", "error");
```

## 工具描述优化

### 改进重点：从"功能说明"到"维护指南"

#### 1. save_memory - 强化维护意识

**改进前**：简单说明三层结构和覆盖规则
**改进后**：
- ✅ 明确三层的**语义定位**（稳定事实 / 偏好模式 / 短期状态）
- ✅ 添加**维护原则**：避免重复、定期清理、精简内容
- ✅ 强调**保存前检查**：先 list 再决定是更新还是新增
- ✅ 降低单条限制：500 → 200 字符（强制精简）

**关键指引**：
```
维护原则：
1. 同一 category 下，相同的 key 会自动覆盖
2. 每条记忆控制在 200 字符以内，聚焦核心信息
3. 定期清理波动区域：项目完成后主动调用 delete_memory
4. 避免重复：保存前先用 list_memory 检查
5. 只记录明确信息，不要记录推测
```

#### 2. list_memory - 强调会话初始化

**改进前**：只说"列出记忆"
**改进后**：
- ✅ 明确**使用场景**：新会话开始、保存前检查、维护清理
- ✅ 强调**工作流**：先 list 看摘要，再决定是否 read 细节

#### 3. delete_memory - 明确删除指南

**改进前**：只说"删除过期记忆"
**改进后**：
- ✅ **何时删除**：列举具体场景（过期条件满足、重复、错误）
- ✅ **不要删除**：明确禁区（稳定画像、仍有效信息）

## 对比效果

### 旧版工具提示（容易产生重复）
```
"记忆是你的工作笔记本，分三层：user_profile（职业、技术背景）、
user_preference（回答风格）、volatile（当前项目）。
相同 category + key 时覆盖旧值。"
```
→ LLM 只知道"可以保存"，不知道"何时该合并、何时该删除"

### 新版工具提示（引导维护行为）
```
"三层结构：
• user_profile：稳定事实。只在用户明确提到时记录，避免推测。
• user_preference：行为模式。只在用户表达明确偏好时记录。
• volatile：短期状态。必须包含过期条件。

维护原则：
1. 避免重复：保存前先用 list_memory 检查
2. 定期清理波动区域：过期后主动 delete_memory
3. 只记录明确信息，不推测
4. 200 字符以内，聚焦核心"
```
→ LLM 知道"何时保存、如何精简、何时删除"

## 实际改进

| 维度 | 改进前 | 改进后 |
|------|--------|--------|
| **内容限制** | 500 字符 | 200 字符 |
| **重复检查** | 不提示 | 明确要求先 list 再保存 |
| **维护意识** | 无 | 强调定期清理 volatile |
| **记录标准** | 无 | 只记录明确信息，不推测 |
| **删除指南** | 模糊 | 明确何时删、何时不删 |

## 预期效果

1. **减少重复**：LLM 会在保存前先 `list_memory` 检查已有记忆
2. **主动清理**：项目完成后会主动 `delete_memory` 清理 volatile
3. **内容精简**：200 字符限制强制 LLM 提炼核心信息
4. **分类准确**：明确三层语义，避免混淆
